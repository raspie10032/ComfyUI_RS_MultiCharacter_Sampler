# Epsilon: point, box and mixed layouts

The character pipe accepts up to **10 active regions in total**, including characters and text. Existing point workflows keep their input order and default behavior. A box controls where a prompt is read; it does not guarantee exact object boundaries, spelling, character count or anatomy.

## Two characters and one word

In **RS MultiCharacter Prompts**, set `character_count` to **3** and `layout_mode` to **mixed**:

| Slot | Kind | Geometry | Prompt / style | Literal text | X / Y | Width / height |
|---|---|---|---|---|---|---|
| 1 | character | point | Description of the left person | — | 0.25 / 0.60 | unused |
| 2 | character | point | Description of the right person | — | 0.75 / 0.60 | unused |
| 3 | text | box (automatic) | Large bold red uppercase title | HELLO | 0.50 / 0.10 | 0.55 / 0.16 |

Connect the pipe to the sampler and choose `layout_method=regional`. Include the scene and total **two** people in the common prompt. Remove `text` from the common negative prompt when requesting visible text. Text is generated by the diffusion model; this is not a font overlay or deterministic typesetting tool.

- **points:** character X/Y centers divide the whole canvas. Duplicate centers are distributed left to right as before. Text slots are inactive in this mode.
- **boxes:** every active region uses an explicit rectangle.
- **mixed:** each character selects `point` or `box`; text always uses a box. Point regions cover the canvas except where boxes claim it. Boxes take precedence over points. Overlapping boxes share their captions rather than giving the first slot exclusive ownership.

X/Y are normalized centers; width and height are fractions of the canvas. Boxes must fit inside the canvas. The node previews points and rectangles together. Small boxes may disappear at a model's coarsest attention grid; an error asks you to enlarge or reposition the region. A box that completely covers a point region likewise raises an error rather than silently dropping that character.

Outside all boxes, common conditioning stays active even when the initial common strength is zero. Within a region, the sampler's existing common/character strength and boundary schedule still apply. `region_feather` applies to point masks; boxes have explicit boundaries. Attention downsampling can move a boundary by a token.

## MOSS native JSON comparison

`layout_method=moss_native` sends the official structured layout to MOSS's normal conditioning path. It requires a MOSS model and **boxes for every region**. Use `layout_mode=boxes`, or mixed mode with every character explicitly set to box. Point regions are rejected with an explanatory error; no automatic rectangle is guessed.

The extension converts normalized rectangles to MOSS's centered pixel `[top, left, bottom, right]` coordinates. Characters use `label=object`; text regions use `label=text`, a separate style caption and literal `text`. See the [official MOSS guide](https://github.com/OpenMOSS/MOSS-Image/blob/main/USERGUIDE.md#layout-prompts-experimental).

Native mode ignores regional strength, boundary and feather controls. Use unweighted literal captions and ComfyUI syntax. The regional mode works with the supported model families, while their ability to draw exact text varies. Native MOSS layout and the 8-step LoRA must be evaluated separately.

## Metadata and detailer

PNG and both WebP formats retain character boxes and text regions in the local metadata extension. Load Image restores them into the same pipe; `use_image_settings` also restores the layout method and generation settings. Ordinary NAI character captions still contain only characters. Autosave does not embed a ComfyUI workflow.

Text regions are excluded from face matching and character counts in the detailer, and retained in saved metadata. For characters with boxes, position matching uses box centers. Text-only pipes can generate an image but cannot perform character face matching. Captions may still influence the whole scene through the model's learned priors.
